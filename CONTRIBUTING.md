# Участие в разработке CupGuide

Спасибо за интерес к проекту! Мы рады любому вкладу в развитие CupGuide.

## Как внести вклад

### 1. Сообщить о проблеме

Если вы нашли баг или хотите предложить улучшение:

1. Проверьте, нет ли уже похожего issue
2. Создайте новый issue с подробным описанием
3. Укажите шаги для воспроизведения (для багов)
4. Приложите логи или скриншоты при необходимости

### 2. Предложить изменения (Pull Request)

1. Сделайте fork репозитория
2. Создайте ветку для изменений:
   ```bash
   git checkout -b feature/my-feature
   ```
3. Внесите изменения
4. Убедитесь, что тесты проходят:
   ```bash
   python -m pytest tests/ -v
   ```
5. Сделайте commit с понятным описанием:
   ```bash
   git commit -m "feat: добавлена функция X"
   ```
6. Отправьте изменения и создайте Pull Request

## Стиль кода

### Python

- Следуйте PEP 8
- Используйте type hints
- Документируйте функции с помощью docstrings
- Максимальная длина строки: 100 символов

### Commits

Используйте conventional commits:
- `feat:` - новая функциональность
- `fix:` - исправление бага
- `docs:` - изменения в документации
- `refactor:` - рефакторинг кода
- `test:` - добавление тестов
- `chore:` - прочие изменения

## Структура проекта

```
├── app/                  # FastAPI Backend
│   ├── api/              # API endpoints
│   ├── services/         # Бизнес-логика
│   ├── models/           # Pydantic модели
│   └── templates/        # HTML шаблоны
├── telegram_bot/         # Telegram Bot
├── tests/                # Тесты
└── data/                 # Данные (JSON)
```

## Тестирование

Перед отправкой PR убедитесь:

```bash
# Запуск всех тестов
python -m pytest tests/ -v

# Проверка типов (опционально)
mypy app/ telegram_bot/
```

## Безопасность

- Никогда не коммитьте секреты и API ключи
- Используйте переменные окружения для конфигурации
- Проверяйте код на уязвимости

## Вопросы

Если у вас есть вопросы, создайте issue с меткой `question`.
